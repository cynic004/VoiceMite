# VoiceMite 维护流程

## 日常开发

1. 同步 `main`，检查本地改动。
2. 完成修改并运行相关测试，按需更新 README、CHANGELOG 和测试报告。
3. 检查提交差异，排除密钥、用户配置、录音、私人文本和构建缓存。
4. 推送后检查 GitHub Actions，处理失败项。

`Windows build and checks` 在推送 `main`、提交 PR 或手动触发时运行：构建解决方案，执行核心测试和模拟目标的 STA 工作线程测试，生成便携包与源码包。构建产物保留 14 天。

桌面测试选项及操作影响见 [贡献指南](../CONTRIBUTING.md)。涉及录音、插入、剪贴板或安装的修改，需要运行对应 Windows 测试。桌面测试串行运行，每轮使用独立输出目录；在 [测试报告](TEST-REPORT.md) 中记录版本、环境、结果及未测项。云端服务测试单独记录所用协议和模型。

## 依赖更新

Dependabot 每月检查 GitHub Actions，Actions 固定到提交 SHA。合并更新前检查上游发布说明、权限变化和 CI 结果。

SDK 版本在 `global.json` 中管理；Inno Setup 版本及下载校验值在发布工作流中管理。升级后运行构建、测试和打包。当前应用没有第三方 NuGet 依赖。

## 发布新版本

1. 更新 `Directory.Build.props` 和 CHANGELOG，版本标签使用 `vMAJOR.MINOR.PATCH`。发布脚本从属性文件读取版本。
2. 运行构建、核心测试和相关桌面测试；检查中英文界面，以及安装、升级、卸载和数据保留。
3. 提交并推送，等待 CI 通过，再创建版本标签。已发布的标签保持不变。
4. 在 Actions 运行 `Prepare draft Windows release`，输入版本标签。工作流构建对应源码、执行非交互测试、校验并安装 Inno Setup 7.1.1，生成发布草稿。
5. 下载并检查安装包、便携 ZIP、源码 ZIP 和 `SHA256SUMS.txt`，确认测试报告对应本次版本。源码包应排除开发工具、构建缓存和用户数据。
6. 在发布说明中填写主要变化、已知问题和签名状态，检查草稿后发布。

也可以使用本地测试过的发布产物：

```powershell
pwsh -File tools/publish.ps1
```

同一次发布的二进制和校验文件应来自同一套产物。发布工作流只创建草稿，遇到同标签已有 release 时停止。它使用仓库 `GITHUB_TOKEN`，仅发布任务具有 `contents: write` 权限，无需配置 STT/LLM 密钥。

## 修复与回退

- 修复通过新提交和补丁版本交付；源码回退使用 revert 提交。
- 应用降级前验证配置兼容，保留用户配置及 DPAPI 密钥。
- 安装前退出 VoiceMite。遇到外部文件锁时说明占用情况，保留其他应用的运行状态。
- 错误插入、密钥泄露或越权访问按 [安全政策](../SECURITY.md) 处理，并在修复版本中说明影响范围。
